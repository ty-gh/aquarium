# aquarium

店舗の 32 インチモニターで流しっぱなしにする「水槽」の HTML。眺めるためのもので、lofi 的な雰囲気。

見た目だけが違う 3 案がある。依頼主に 1 つ選んでもらう。

## ファイル

| ファイル | 中身 |
|---|---|
| `pixel.html` | A 案。ピクセルアート（320×180 を拡大・32 色）。魚 5 種 19 匹 |
| `paper.html` | B 案。フラットな切り絵イラスト（くすんだ 12 色）。魚 5 種 17 匹 |
| `glow.html` | C 案。やわらかい光のグラデーション（暗めの室内向け）。魚 5 種 20 匹 |
| `aquarium.html` | まとめ版。3 案をボタンで切り替えられ、全画面にもできる |
| `index.html` | URL の入口。中身は `aquarium.html` と同じ |
| `build.mjs` | 3 案から `aquarium.html` と `index.html` を作る |
| `shots/` | 3 案の昼・夕・夜の画面（`pixel_day.png`、`paper_dusk.jpg` など） |
| `before/` | 添削を出す前の版と画面 |

単体の 3 ファイルは画面に何も出さず、マウスとキーに反応しない。操作できるのはまとめ版だけ。

## 使い方

URL を開くか、HTML を 1 つ機器にコピーしてブラウザで開く。コピーして使うなら、ほかのファイルもネット接続も要らない。

20 分で昼 → 夕方 → 夜 → 昼と色が移る。

まとめ版の操作:

| 操作 | 動き |
|---|---|
| マウスを動かす・画面に触れる | 下にボタン（ピクセル／切り絵／光／全画面）が出る。3 秒で消える |
| 案のボタンを押す | その案に切り替わる |
| 1・2・3 キー | ピクセル・切り絵・光に切り替わる |
| ← → キー | 前後の案に切り替わる |
| 「全画面」ボタン・F キー | 全画面にする。もう一度で戻る（Esc でも戻る） |

選んだ案はブラウザが覚え、次に開いたときもその案で始まる。

全画面はブラウザの決まりで、ボタンかキーを押したときにしか入れない。開いただけで全画面にしたいときは、ブラウザをキオスクモードで起動する。

単体の 3 ファイルを全画面にするときは、ブラウザの操作を使う（Windows は F11、Mac は control + command + F）。Mac の Chrome はツールバーが残る設定のことがある（「表示」メニューで外す）。

3 案のどれかを直したら、`node build.mjs` でまとめ版を作り直す。

## 状態（2026-11-25）

3 案とも、制作 → 統括の確認 → 添削 1 回 → 再確認まで済み。そのあと、まとめ版を作って公開した。

3 案で確かめたこと（Mac のヘッドレス Chrome で実時間再生）:

- 60fps で動く
- 1920×1080・縦置き 1080×1920・3840×2160 で全面に表示される
- コンソールエラーと外部通信が無い
- 600 倍速で 5 時間半ぶん進めても、魚・泡・粒の数が増えない
- 1.5 秒おき 16 コマ（24 秒ぶん）を並べて見て、魚が飛んだり急に現れたりしない

まとめ版で確かめたこと:

- キー・ボタンのクリック・連打のどれでも切り替わり、中で動く案は常に 1 つ
- マウスを動かすとボタンが出て、放置するとボタンもカーソルも消える
- 再読み込みしても、選んだ案で始まる
- 3 案とも 60fps。横置き・縦置き・4K で全面に表示される
- 窓ありの Chrome で、F キーとボタンのどちらでも全画面に入れて戻れる。全画面のまま案を切り替えられる
- 公開 URL から配信される HTML が手元のファイルと一致する。公開 URL を開いて、まとめ版・案の指定・1 案だけのどれも動く

公開 URL では、ブラウザが自動で取りに行くタブ用アイコンが無いという 404 がコンソールに 1 行出る。表示には影響しない。

未確認:

- 動いている画面を人の目で続けて見ること（確かめたのは静止画とコマ並べまで）
- 実機のモニターでの見え方（色・明るさ・離れて見たときの魚の大きさ）
- 再生する機器での動作の軽さ（機器が未定）
- 何日も続けて流したときの挙動（確かめたのは早送りまで）
- Chrome 以外のブラウザ
- まとめ版のタッチ操作、Esc で全画面から戻る動き、公開 URL 上での全画面

## 添削

各案に 1 回ずつ出した。修正は 1 回で締めたので、残っている点は直していない。

| 案 | 指摘 | 修正後 | 残っている点 |
|---|---|---|---|
| A | 時間がたつと魚が片側に寄り、画面内の数も減る／群れが団子状に重なる／底の魚が岩や草の陰に隠れる／泡が常時 2 本出ていて輪が大きい | 画面内は常に 17 匹以上で、左右の偏りは 7 割未満。群れは横長の隊形。底の魚は手前の砂の上を歩く。泡は出ている時間が約 15% | 群れの並びがやや規則的。魚が向きを変える回数が増えた（1 匹あたり 1 分に約 1 回 → 1.4〜2.7 回）。添削で「左右どちらかに 7 割以上寄らない」を求めた結果で、落ち着きなく見えないかは未確認 |
| B | 水の横縞が 10 段ほどあり目立つ／夕方が灰色で暖色に見えない／小さい魚が小さすぎる／魚が 1 か所に重なる／群れが抜けると 8〜9 匹に減り、縦置きは上 3 分の 1 が空く／底の魚が陰に入る | 縞は 4 段の波形。夕方は桃色。小さい魚は約 1.45 倍。群れは画面外へ出ない。底の魚は手前の砂を歩く | 夕方の桃色が強く、主役の金魚が水の色に近づく。縦置きでは魚のひれが短時間重なる |
| C | 主役のエンゼルフィッシュが灰色の球に板が付いたように見える／小さい魚が小さすぎる／発光と光の表現が弱い／夕方が夜と見分けられない／群れが輪になる／最下端に草の先だけがのぞく | 主役は平たい体に描き直した。小さい魚は約 1.5 倍。夕方は桃〜紫になり、夜は発光が分かる。草先は消した | 主役が灰色の縞で地味。底の魚どうしが重なる場面がある |

## 検証用の口

画面には何も出ない。

- `?speed=N` で時間の進みを N 倍にする（例: `pixel.html?speed=60` で 20 秒が 1 周）
- ブラウザのコンソールで `__stats()` を呼ぶと、魚・泡・粒の現在数が返る

## 3 案に共通の仕様

- 魚 4〜5 種・14〜22 匹（群れ 1 種・大きめの主役 1 種・底にいる種 1 つ）、揺れる水草、岩と流木、砂底、ときどき立ちのぼる泡、光の筋、漂う粒
- 文字・時計・ロゴ・操作 UI・音は無い。マウスとキーに反応しない。カーソルは隠す
- 魚・泡・粒の数に上限がある。Canvas 2D のみ。内部の描画サイズに上限がある
- HTML 1 ファイルで完結し、`file://` で開いて動く
